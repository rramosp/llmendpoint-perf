# `llmendpoint-perf` Metrics Reference

`llmendpoint-perf` collects granular per-request streaming telemetry (`runs/<run-id>/calls.jsonl`) and computes run-level statistical distributions, throughput, reliability, SLO goodput, and cost efficiency metrics (`runs/<run-id>/results.jsonl`).

---

## 1. Streaming Measurement Timeline

To accurately separate prompt prefill and queueing delay from autoregressive token generation speed, `llmendpoint-perf` sends every benchmark request using Server-Sent Events (`stream: true`, `stream_options: {"include_usage": true}`).

For each request, four high-resolution monotonic timestamps (`time.perf_counter()`) are recorded:

```text
t_start                t_first_token                        t_last_token     t_end
  │                          │                                    │            │
  ├─────── TTFT (ms) ────────┼────── Decode Window (secs) ────────┼─ Teardown ─┤
  │  (Network + Queueing +   │   (Output Token #2 ... Token #N)   │            │
  │    Prompt Prefill)       │   TPOT = Decode Window / (N - 1)   │            │
  └──────────────────────────┴────────────────────────────────────┴────────────┘
                                E2E Latency (ms)
```

* **`t_start`** (`timestamp_start`): Recorded immediately before sending the HTTP `POST /chat/completions` request.
* **`t_first_token`** (`timestamp_first_token`): Recorded upon receiving the first SSE chunk containing non-empty `delta.content` or `delta.reasoning_content` / `delta.reasoning`.
* **`t_last_token`**: Updated on each subsequent SSE chunk containing generated content or reasoning tokens.
* **`t_end`** (`timestamp_end`): Recorded when the SSE stream finishes (`data: [DONE]` or stream close).

## 2. Per-Request Latency & Speed Metrics (`calls.jsonl`)

Each completed request writes a `CallRecord` entry to `runs/<run-id>/calls.jsonl` with the following timing and speed metrics:

| Metric Key | Report Label | Unit | Formula / Definition | What It Measures |
| :--- | :--- | :---: | :--- | :--- |
| `ttft_ms` | **TTFT (ms)** | `ms` | $(t_{\text{first\_token}} - t_{\text{start}}) \times 1000$ | **Time to First Token**: Elapsed time from dispatching the request to receiving the first generated output or reasoning token. Captures network RTT, load-balancer/scheduler queueing delay, and prompt prefill (plus vision encoding for multimodal inputs). Set to `null` if the request failed. |
| `tpot_ms` | **TPOT / ITL (ms/tok)** | `ms/tok` | $\dfrac{(t_{\text{last\_token}} - t_{\text{first\_token}}) \times 1000}{\text{output\_tokens} - 1}$ | **Time Per Output Token (Inter-Token Latency)**: Average time between consecutive generated tokens after the first token arrives. Reflects autoregressive decode step latency. If `output_tokens <= 1` or the response arrived in a single chunk, `tpot_ms` is `0.0`. Set to `null` if the request failed. |
| `e2e_latency_ms` | **E2E Latency (ms)** | `ms` | $(t_{\text{end}} - t_{\text{start}}) \times 1000$ | **End-to-End Request Latency**: Total wall-clock time from request dispatch until stream completion (`[DONE]`), equal to $\text{TTFT} + \text{TPOT} \times (\text{output\_tokens} - 1)$ plus stream close overhead. Recorded for both succeeded and failed requests. |
| `output_tokens_per_sec` | **Decode Speed (tok/s)** | `tok/s` | $\dfrac{\text{output\_tokens}}{t_{\text{last\_token}} - t_{\text{first\_token}}}$ | **Per-Request Decode Throughput**: Token generation rate during the active decode window $(t_{\text{last\_token}} - t_{\text{first\_token}})$ for a single request. If the entire response arrived in a single chunk ($t_{\text{last\_token}} = t_{\text{first\_token}}$), falls back to $\text{output\_tokens} / (\text{e2e\_latency\_ms} / 1000)$. |

## 3. Token Accounting Metrics (`calls.jsonl` & `results.jsonl`)

`llmendpoint-perf` extracts token counts from the final SSE `usage` chunk (requested via `stream_options: {"include_usage": true}`). If an endpoint does not return `usage` metadata, deterministic heuristic estimators are used as a fallback.

### Per-Request Token Fields (`calls.jsonl`)
| Metric Key | Description | Source & Fallback Behavior |
| :--- | :--- | :--- |
| `input_tokens` | Number of prompt tokens processed by the model for this request. | Extracted from `usage.prompt_tokens`. If omitted by the server, estimated from message text (~1.3 tokens/word or `chars / 4`, plus `4` framing tokens per message and `258` tokens per attached multimodal `image_url`). |
| `output_tokens` | Number of completion tokens generated by the model for this request. | Extracted from `usage.completion_tokens`. If omitted by the server, estimated as the maximum of the non-empty SSE token chunk count and the text token estimate of `response_content`. |
| `reasoning_tokens` | Number of internal thinking/reasoning tokens consumed before or during output generation. | Extracted from `usage.completion_tokens_details.reasoning_tokens` (defaults to `0` if not reported). |
| `cached_input_tokens` | Number of input tokens served from the endpoint's prefix/context cache. | Extracted from `usage.prompt_tokens_details.cached_tokens` (defaults to `0` if not reported). |

### Run-Level Token Volume Totals (`results.jsonl`)
Summed across all **succeeded** (`HTTP 200`) requests in the benchmark run:
* **`total_input_tokens`**: $\sum \text{input\_tokens}$
* **`total_output_tokens`**: $\sum \text{output\_tokens}$
* **`total_reasoning_tokens`**: $\sum \text{reasoning\_tokens}$
* **`total_cached_input_tokens`**: $\sum \text{cached\_input\_tokens}$

## 4. Statistical Distribution Aggregations (`results.jsonl`)

For each of the six core per-request metrics (`ttft_ms`, `tpot_ms`, `e2e_latency_ms`, `output_tokens_per_sec`, `input_tokens`, and `output_tokens`), `llmendpoint-perf` computes a `DistributionStats` summary across all **succeeded** requests (excluding warmup requests):

| Statistic | Description |
| :--- | :--- |
| `count` | Number of succeeded requests included in the distribution. |
| `mean` | Arithmetic mean across all succeeded requests. |
| `std` | Population standard deviation ($\sigma$), measuring latency or token-length variability. |
| `min` | Minimum observed value across the run. |
| `p50` | **50th percentile (Median)**: Typical user experience; half of requests completed at or below this value. |
| `p90` | **90th percentile**: Tail latency threshold exceeded by 10% of requests. |
| `p95` | **95th percentile**: High-load tail latency indicator; standard SLA benchmark target. |
| `p99` | **99th percentile**: Extreme tail latency capturing worst-case queueing spikes or garbage-collection/batching stalls. |
| `max` | Maximum observed value across the run. |

> **Note**: In `llmendpoint-perf inspect`, all eight statistics (`Mean`, `Std`, `Min`, `p50`, `p90`, `p95`, `p99`, `Max`) are displayed. In `llmendpoint-perf compare`, `Mean`, `p50`, `p95`, and `p99` are displayed side-by-side across runs for all six metrics.

## 5. System Throughput, Reliability & SLO Goodput (`results.jsonl`)

Let $D$ (`actual_duration_secs`) be the total wall-clock duration in seconds of the measured benchmark phase (excluding warmup).

### Request Counts & Reliability
| Metric Key | Unit | Formula / Definition |
| :--- | :---: | :--- |
| `total_requests` | requests | Total measured requests dispatched and completed (succeeded + failed). |
| `succeeded_requests` | requests | Number of requests returning `HTTP 200` with `error == null`. |
| `failed_requests` | requests | Number of requests that returned a non-200 HTTP status or raised a client/timeout exception. |
| `slo_satisfied_requests` | requests | Number of succeeded requests whose latencies satisfied **all** non-null bounds in `evaluation.slo` (`ttft_ms <= max_ttft_ms`, `tpot_ms <= max_tpot_ms`, and `e2e_latency_ms <= max_e2e_ms`). |
| `success_rate` | `%` | $\left(\dfrac{\text{succeeded\_requests}}{\text{total\_requests}}\right) \times 100$ |
| `error_rate` | `%` | $\left(\dfrac{\text{failed\_requests}}{\text{total\_requests}}\right) \times 100$ |
| `errors_by_type` | `dict[str, int]` | Breakdown of failed requests grouped by HTTP status code (e.g., `HTTP_429`, `HTTP_503`) or exception type (e.g., `ReadTimeout`). |

### System Throughput (`results.throughput`)
| Metric Key | Report Label | Unit | Formula | Description |
| :--- | :--- | :---: | :--- | :--- |
| `throughput.rps` | **Request Throughput (RPS)** | `req/s` | $\dfrac{\text{total\_requests}}{D}$ | Total completed requests per second (including failed requests). |
| `throughput.goodput_rps` | **Goodput** | `req/s` | $\dfrac{\text{succeeded\_requests}}{D}$ | Successful (`HTTP 200`) requests completed per second. |
| `throughput.slo_goodput_rps` | **SLO Goodput (RPS)** | `req/s` | $\dfrac{\text{slo\_satisfied\_requests}}{D}$ | Requests per second that both succeed and meet all user-configured latency SLO thresholds (`max_ttft_ms`, `max_tpot_ms`, `max_e2e_ms`). If no SLO bounds are configured, `slo_goodput_rps == goodput_rps`. |
| `throughput.output_tps` | **Output Throughput (tok/s)** | `tok/s` | $\dfrac{\text{total\_output\_tokens}}{D}$ | Aggregate output tokens generated per second across all concurrent worker threads. Primary measure of serving decode capacity under load. |
| `throughput.input_tps` | **Input Throughput (tok/s)** | `tok/s` | $\dfrac{\text{total\_input\_tokens}}{D}$ | Aggregate prompt tokens processed per second across all concurrent worker threads. |
| `throughput.total_tps` | **Total Throughput (tok/s)** | `tok/s` | $\dfrac{\text{total\_input\_tokens} + \text{total\_output\_tokens}}{D}$ | Combined input + output tokens processed per second by the endpoint. |

## 6. Cost Efficiency Metrics (`calls.jsonl` & `results.jsonl`)

When token prices are configured under `evaluation.pricing` (in USD per 1,000,000 tokens: $P_{\text{in}} = \text{input\_per\_1m\_tokens}$, $P_{\text{cached}} = \text{cached\_input\_per\_1m\_tokens}$, $P_{\text{out}} = \text{output\_per\_1m\_tokens}$), `llmendpoint-perf` computes:

| Metric Key | Report Label | Unit | Formula | Description |
| :--- | :--- | :---: | :--- | :--- |
| `cost_usd` *(per call)* | **Request Cost** | `USD` | $\dfrac{\max(\text{in} - \text{cached}, 0)}{10^6} P_{\text{in}} + \dfrac{\text{cached}}{10^6} P_{\text{cached}} + \dfrac{\text{out}}{10^6} P_{\text{out}}$ | Exact dollar cost of an individual succeeded request, discounting cached prompt tokens from uncached input tokens. |
| `cost.total_cost_usd` | **Total Cost (USD)** | `USD` | $\sum \text{cost\_usd}$ | Total cumulative dollar cost of all succeeded requests in the run. |
| `cost.mean_cost_per_request_usd` | **Mean Cost / Req (USD)** | `USD/req` | $\dfrac{\text{total\_cost\_usd}}{\text{succeeded\_requests}}$ | Average dollar cost per successful request. |
| `cost.cost_per_1k_output_tokens_usd` | **Cost / 1K Out Tokens (USD)** | `USD / 1K out tok` | $\dfrac{\text{total\_cost\_usd}}{\text{total\_output\_tokens} / 1000}$ | Effective blended cost (including prompt prefill cost) normalized per 1,000 generated output tokens. |
| `cost.cost_per_1k_total_tokens_usd` | **Cost / 1K Total Tokens (USD)** | `USD / 1K tok` | $\dfrac{\text{total\_cost\_usd}}{(\text{total\_input\_tokens} + \text{total\_output\_tokens}) / 1000}$ | Effective blended cost normalized per 1,000 total (input + output) tokens. |
| `cost.output_tps_per_usd_per_hour` | **Throughput per Dollar** | `(tok/s) / (USD/hr)` | $\dfrac{\text{output\_tps}}{(\text{total\_cost\_usd} / D) \times 3600}$ | Cost-efficiency ratio measuring how many output tokens per second the endpoint delivers per USD/hour of spend. |
